# ADR-0018: Мультиформатный ingest RAG и база знаний о проекте (docs + code)

- **Статус:** accepted
- **Дата:** 2026-10-02
- **Контекст:** ADR-0017 закрыл RAG на markdown/text. Требование владельца: ВБД содержит базу знаний о проекте, **включая код**, и умеет **PDF** и **Excel**. В репозитории: ~200 файлов кода (`.ps1`, `.py`, `.ts/.tsx`, `.sql`), архитектура как текст (`.dsl`, `.puml`, OpenAPI, `.bpmn`, `.drawio`), 3 PDF (один — слайды, вероятно без текстового слоя), 2 Excel-калькулятора, где смысл — в формулах.
- **Рассмотренные альтернативы:**
  - **Все форматы через LlamaIndex readers целиком** — отклонено: нужен контроль над локаторами (страница, лист, строки) и чанкингом по синтаксису; readers дают это нестабильно.
  - **OCR через Tesseract** — отклонён владельцем в пользу **vision-модели через LiteLLM** (понимает слайды и схемы, нет системной зависимости); цена — токены и зависимость от ключа.
  - **PyMuPDF** — отклонён: лицензия AGPL; взяты **pypdf** (BSD) для текста и **pypdfium2** (BSD/Apache) для рендера страниц.
  - **Одна коллекция для документов и кода** — отклонена: разные чанкинг, язык BM25 и аудитория; **две коллекции**: `project-docs`, `project-code`.
  - **Саммари кода внутри сервиса RAG** — отклонено: сервис остаётся универсальным; саммари генерирует инструмент синхронизации (`kb-sync`) и загружает их как обычные документы.
  - **GraphRAG / граф вызовов** — отложено.
- **Решение:**
  - **Контракт 0.2.0:** стратегии чанкинга `auto | markdown | sentence | token | code | pages | table` (по умолчанию `auto`); `Locator` (path, page, sheet, range, line_start/end, symbol, section) в `Chunk` и `Citation`; `content_hash` в `DocumentIngest`/`Document` (пропуск переиндексации); `sparse_language` на коллекции; `MinioSource.content_type`.
  - **Парсеры** (`apps/rag/alexsoft_rag/parsers/`): реестр по расширению; каждый возвращает сегменты `{text, locator, kind}`; чанкер применяет стратегию к сегментам. Код — единицы по определениям: `py` через стандартный `ast` (большие классы делятся на методы), `ts/tsx/js` по объявлениям (regex, большие классы — на методы), блочное деление для ps1/sql/yaml/toml/dsl/puml/conf; мелкие соседние единицы склеиваются до `chunk_size`; заголовок чанка `File / Language / Symbol / Lines`, в локаторе `line_start/line_end/symbol` — номера строк исходного файла. Excel — `openpyxl`: таблицы листов группами строк с повтором шапки (пустые колонки отбрасываются; широкие/разреженные листы — записями `колонка: значение`) + отдельные чанки формул (`data_only=False` и `True`), скрытые листы пропускаются. PDF — `pypdf`; страницы без текста → PNG (`pypdfium2`) → vision-модель (`RAG_VISION_MODEL`, алиас `vision` в LiteLLM, по умолчанию `openai/gpt-4o-mini`); результат кешируется по sha256 страницы в `rag.page_ocr_cache`. `.bpmn`/`.drawio` — XML → список узлов и связей.
  - **BM25:** язык на коллекцию (`sparse_language`); для кода к sparse-тексту добавляются разбитые идентификаторы (`snake_case`, `camelCase`).
  - **Источники КБ** — декларативно в `apps/rag/kb/sources.yaml`; `kb-sync` берёт файлы из `git ls-files`, исключает секреты и бинарщину, считает `content_hash`, грузит в MinIO (`rag-docs/<prefix>/…`), вызывает ingest, удаляет документы исчезнувших файлов, генерирует саммари кода через LiteLLM (кеш по хешу).
  - **Секреты:** `.env*` (кроме `.env.example`), `*.pem`, `*.key`, `credentials.json` — по имени; остальные файлы — регулярные проверки (ключи `sk-…`, приватные ключи, `password = "…"` с не-placeholder значением). Подозрительный файл не загружается и попадает в отчёт.
- **Последствия:**
  - Новые зависимости сервиса: `pypdf`, `pypdfium2`, `openpyxl`, `pyyaml`.
  - **tree-sitter отвергнут по факту** (проверено 2026-10-02): нативный Python-биндинг (`tree-sitter` 0.25/0.26 + грамматики) на Windows портил кучу — случайные `access violation` в несвязанном коде (tiktoken, importlib), даже без тестов, на простом цикле `parse`. Для долгоживущего сервиса неприемлемо; вернуться можно при выходе исправленной версии, интерфейс парсера (`Segment` с локатором) от этого не зависит.
  - Клиент Qdrant создаётся с `check_compatibility=False`: фоновая проверка версии через httpx в отдельном потоке тоже падала с `access violation` на Windows (чтение системного хранилища сертификатов).
  - В LiteLLM — алиас `vision`; расход токенов на OCR страниц-картинок (разовый, с кешем).
  - Excel-арифметика не решается поиском; для расчётов нужен инструмент агента (калькулятор агента 1).
  - Для запроса по двум коллекциям агент вызывает RAG дважды; `collections: [...]` — возможное расширение.
  - Публичный доступ к `project-code` — только после IAM (этап 6), как и ко всему RAG.
