Контракт RAG-сервиса (apps/rag) — три слоя - загрузка, хранение эмбеддингов, поиск.

Контракт-первый (contract-first) для сервиса apps/rag (LlamaIndex + Qdrant). Источник архитектуры: artifacts/architecture/c4-l1-l2-l3.dsl, ADR-0015.

Три слоя

  1. Загрузка (ingest) — документ из MinIO или inline-текст → Parser & Clean → Chunking → embedding → upsert в Qdrant. Выполняется асинхронно, возвращается Job.
  2. Хранение эмбеддингов — коллекции Qdrant (dense + sparse), документы и их чанки.
  3. Поиск (retrieval) — hybrid search в Qdrant (dense + sparse, fusion), опционально grounded-ответ с цитатами.

Внешние зависимости сервиса

  • LiteLLM — единственный путь к моделям: embedding text-embedding-3-small (ingest и query embedding) и LLM для /v1/query. Модель embedding задаётся конфигурацией сервиса и не передаётся клиентом (иначе векторы разных моделей смешаются в одной коллекции).
  • LLM Guard — синхронная проверка входа/выхода /v1/query; при блокировке — ошибка guardrail_blocked.
  • MinIO — исходные документы. Qdrant — векторы и payload чанков.

Потребители

  • Agent Platform (LangGraph / LangFlow / Dify) — POST /v1/search, POST /v1/query.
  • FastAPI BL / админ — управление коллекциями и документами.

Безопасность

Сервис внутренний (за Nginx / во внутренней сети). Этап 5 — X-API-Key; этап 6 — JWT от Authentik (bearerAuth). Публичная выдача наружу — только после IAM.

Соглашения

  • Версия в пути: /v1. Время — RFC 3339 UTC. Идентификаторы — UUID.
  • Ошибки — application/problem+json (RFC 9457).
  • Корреляция: заголовок X-Request-Id принимается и возвращается; traceparent (W3C) пробрасывается в LangSmith / Loki.

Слой поиска — hybrid search и ответы с цитатами.

Hybrid-поиск чанков

Query embedding (через LiteLLM) → hybrid search в Qdrant (dense + sparse, fusion) → опциональный rerank → топ-K чанков. Без генерации и без LLM Guard.
